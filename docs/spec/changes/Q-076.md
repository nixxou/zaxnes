# Q-076 — Le critère « aucun jeu en double » d'AMD-037 §4 sur une installation 2.0

Date : 2026-10-30 | Auteur : R3 (côté propre) | Lot : V2-1 (AMD-039)

## 1. L'ambiguïté

AMD-039 §4 reprend les critères d'AMD-030 §6 et les étend à une installation de 3dSen 2.0 : 101
profils importés, 0 en échec, 101 déjà présents au second import, et **pas** de comparaison
d'empreintes avec l'inventaire de référence, qui décrit la 1.1.2 (§5).

Il reste un critère d'une autre amendement qui compare, lui aussi, l'installation aux profils de
référence : **AMD-037 §4, deuxième puce, second cas** — « avec le dossier d'assets du catalogue,
aucun jeu n'apparaît deux fois », parce que chacun des 101 fichiers importés est, octet pour
octet, un profil intégré. Sur une installation 2.0, cela n'est plus vrai : d'après AMD-039 §5,
quatre profils (`DQ3_DW3`, `Final_Fantasy_USA`, `Super Mario Bros`, `punchout`) diffèrent de ceux
de la 1.1.2 par leurs scripts Lua.

Mesuré sur une installation réelle de la 2.0, avec le dossier d'assets de référence (la 1.1.2) :

- 97 des fichiers importés sont reconnus identiques au profil intégré et n'ajoutent rien ;
- les 4 autres restent des profils utilisateur ; ils **portent un identifiant**, et cet identifiant
  n'est aucun de ceux du catalogue (leurs en-têtes diffèrent aussi : deux d'entre eux portent le
  titre « Tetris ») ;
- la bibliothèque compte donc 101 + 4 = 105 entrées : pour ces quatre jeux, l'entrée intégrée et
  l'entrée du profil importé coexistent.

AMD-039 ne dit pas si le critère d'AMD-037 §4 reste exigé tel quel sur une 2.0 — ce qui demanderait
que l'import reconnaisse ces quatre profils comme « le même jeu » malgré des octets et un
identifiant différents — ou s'il ne concerne, comme la comparaison d'empreintes, que la 1.1.2.

## 2. Le choix provisoire

Dans ce lot (qui ne porte que sur la lecture du bundle, AMD-039 §2), le critère d'AMD-037 §4 est
tenu pour **décrit sur la 1.1.2** :

- le test facultatif correspondant vérifie, sur une 2.0, ce qui est mesuré : 97 profils reconnus
  identiques, exactement les quatre profils d'AMD-039 §5 conservés, des identifiants tous
  distincts, et 105 entrées de bibliothèque ;
- sur une 1.1.2 il vérifie le critère inchangé : aucun profil conservé, 101 reconnus identiques,
  une entrée par jeu et des titres tous distincts ;
- le comportement de l'import n'est pas modifié : aucune règle de rapprochement par titre ou par
  contenu partiel n'a été inventée.

Raison : AMD-039 §5 range ces quatre profils du côté d'AMD-040 §1 (les scripts Lua), et inventer
ici un rapprochement serait un changement de règle d'import, que ni AMD-030 §2 ni AMD-037 ne
prévoient.

## 3. Ce qu'il faudrait trancher

1. Sur une installation 2.0, ces quatre profils doivent-ils apparaître comme des jeux de plus
   (état actuel), ou remplacer l'entrée intégrée du même jeu ? Si c'est le second cas, sur quoi se
   fait le rapprochement, puisque ni l'identifiant ni les octets ne coïncident ?
2. Le dossier d'assets de référence doit-il être mis à jour sur la 2.0 (les quatre profils et leurs
   scripts Lua), ce qui ferait disparaître la question — c'est peut-être ce que prévoit AMD-040 ?

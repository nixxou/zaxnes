# Q-064 — Le soleil, la lune et les nuages des skyboxes procédurales : paramètres ou interdits ?

**Ouvert par** : R3, implémenteur, côté propre
**Date** : 2026-10-21 (phase P7, lot P7a)
**Documents concernés** : `changes/AMD-024-p7-assets-libres.md` REQ-PUB-003, `SPEC-06-scene-rendu.md` REQ-SCN-050
**Priorité** : P2 — visible à l'écran
**Statut** : choix provisoire appliqué, référencé `// Q-064` dans le code

## 1. La contradiction

REQ-PUB-003 (AMD-024) demande que les skyboxes Gradient et Fantasy soient procédurales
« **avec les paramètres fonctionnels de SPEC-06 (couleurs, rotation, soleil et lune, nuages,
étoiles)** ». L'inventaire `legal/P7-ASSET-INVENTORY.md` va dans le même sens : les textures
`Sun_LP_01.png` et `Moon_LP_01.png` sont « remplacées par des disques procéduraux dans le shader
de skybox ».

REQ-SCN-050 (SPEC-06, gelée) dit en revanche, pour la skybox Gradient :

> Le soleil, la lune et les nuages du paquet de skybox d'origine **sont désactivés**.

Et son critère d'acceptation décrit un ciel qui ne contient que le dégradé et les étoiles :
« direction horizontale → sRGB (104, 136, 252) ±3 ; zénith → … ; nadir → … ; pas d'étoiles ».
Un disque de soleil visible ferait échouer ce critère, puisque la couleur ne serait plus uniforme
par bande de hauteur.

SPEC-06 §4 ne liste par ailleurs **aucun réglage** de soleil, de lune ou de nuages : les seuls
paramètres de la skybox sont `Skybox` (−1, 0, 1, 2) et la couleur personnalisée. Il n'existe donc
pas de « paramètre fonctionnel de SPEC-06 » pour ces trois corps.

## 2. Les deux lectures

- **(A)** REQ-PUB-003 ajoute le soleil, la lune et les nuages à l'image : la skybox procédurale
  les affiche. REQ-SCN-050 est alors contredite, et son critère d'acceptation exécutable
  (horizon / zénith / nadir) devient infalsifiable.
- **(B)** REQ-PUB-003 demande que le **code sache** les produire — c'est-à-dire que les disques et
  les nuages existent dans le shader, pilotés par des paramètres — mais laisse à SPEC-06 le soin
  de dire s'ils sont allumés. REQ-SCN-050 les éteint, donc ils sont éteints par défaut.

## 3. Le choix provisoire de l'implémenteur

**Lecture (B).** Le shader de skybox contient bien un soleil procédural, une lune procédurale et
une couche de nuages procéduraux, tous paramétrés (direction, taille angulaire, couleur, netteté
du bord, couverture et densité des nuages). Ces paramètres sont rassemblés dans
`SkyBodySettings` (`src/Sen.Render/SkyBodies.cs`) et **leurs gains valent 0 par défaut**, ce qui
reproduit exactement le « sont désactivés » de REQ-SCN-050 : l'image par défaut est le dégradé et
les étoiles, et les critères d'acceptation de REQ-SCN-050 et REQ-SCN-051 passent inchangés.

Un hôte ou un test peut les allumer (`SceneSettings.SkyBodies`), ce qui rend le critère de
REQ-PUB-003 — « changer ses paramètres change l'image » — observable sur les trois corps comme sur
les couleurs et la rotation.

## 4. Référence en code

- `src/Sen.Render/SkyBodies.cs` — les paramètres et leurs défauts éteints.
- `src/Sen.Render/Gl/ProceduralSkyShaders.cs` — les disques et les nuages dans le GLSL.
- `tests/Sen.Render.Tests/ProceduralAssetsTests.cs` — l'image par défaut sans corps célestes, et
  l'image avec.

## Réponse R0 (2026-10-21, normative)
Autorisés et attendus : le soleil, la lune, les nuages, les étoiles et la nébuleuse sont **générés par le shader** (aucune image), pilotés par les paramètres fonctionnels de SPEC-06 (couleurs, rotation, présence). Leur aspect est libre (D, AMD-024).

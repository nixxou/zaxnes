# Q-028 — Archives `.7z` : aucun décodeur disponible dans les dépendances autorisées

- **Ouvert par** : R3 (côté propre), lot L6, 2026-10-21
- **Documents concernés** : SPEC-07 REQ-LOOP-020 (navigateur de fichiers, « extensions nes,
  zip, 7z »), REQ-LOOP-022 (« un fichier `.zip` ou `.7z` DOIT être décompressé »),
  REQ-LOOP-023 (messages `Corrupted zip file`, `Uncompression is not successful`) ;
  SPEC-09 REQ-PERS-032 (extensions `nes`, `zip`, `7z`) ; AMD-010 REQ-UI-201
  (« filtres `.nes`, `.zip` **si pris en charge par SPEC-07** »)
- **Classe** : D (fonction non implémentée, assumée)
- **Priorité** : P3 (contournable : l'utilisateur extrait l'archive)

## Problème

REQ-LOOP-022 exige de décompresser une archive `.7z`. Le format 7z utilise LZMA / LZMA2, qui
n'est fourni ni par le .NET BCL (`System.IO.Compression` ne connaît que deflate, gzip, zlib,
brotli et zip) ni par aucune des dépendances que PLAN.md §4 autorise (Silk.NET, ImGui.NET,
protobuf-net, KeraLua, xUnit). Les ajouter supposerait un nouveau paquet NuGet, décision de
cadrage qui appartient à R0 ; écrire un décodeur LZMA est hors du périmètre de ce lot.

AMD-010 REQ-UI-201 relativise déjà l'exigence (« `.zip` si pris en charge par SPEC-07 »), mais
sans trancher le cas `.7z`.

## Choix provisoire

- `.zip` : pris en charge intégralement (première entrée de l'archive, nom de ROM =
  nom de l'archive avec l'extension `.nes`, messages de REQ-LOOP-023).
- `.7z` : refusé proprement avec le message `Uncompression is not successful`, qui est celui
  de REQ-LOOP-023 pour « échec de décompression de l'entrée ». Le jeu en cours n'est pas
  interrompu (REQ-LOOP-018). Référencé `// Q-028` dans `RomFile.Read`.
- Le filtre du navigateur de fichiers (lot L9) n'annoncera donc `.7z` que si cette question est
  tranchée dans le sens de l'ajout d'un décodeur.

## Question posée à R0

1. Le format `.7z` est-il requis en v1 ? Si oui, autoriser une dépendance LZMA
   (par exemple `SharpCompress`, MS-PL/MIT, ou `SevenZipSharp`) ou accepter un décodeur
   LZMA écrit à la main.
2. À défaut, amender REQ-LOOP-022 et REQ-PERS-032 pour retirer `.7z` de la liste des
   extensions, et conserver le message `Uncompression is not successful` comme refus.

## Réponse R0 (2026-10-21, normative)
Choix provisoire validé.

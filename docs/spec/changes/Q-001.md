# Q-001 — Langue et littéralité des messages d'erreur du cœur

- **Ouvert par** : R3 (côté propre), lot L1a, 2026-10-20
- **Documents concernés** : SPEC-02 REQ-CORE-011, REQ-CORE-091, REQ-CORE-120 ; SPEC-10 (affichage) ; SPEC-07
- **Classe** : C (ambiguïté)
- **Priorité** : P3 (n'empêche pas l'implémentation ; affecte un critère d'acceptation)

## Ambiguïté

REQ-CORE-011 donne les causes d'échec du chargement d'une ROM sous forme de **phrases
françaises entre guillemets** : « en-tête corrompu », « mapper N non supporté », « fichier
tronqué ». REQ-CORE-091 fait de même avec « savestate corrompu ». On ne sait pas si ce sont :

1. des **descriptions de la cause** à rendre dans la langue de l'interface, ou
2. des **chaînes littérales** exigées telles quelles.

REQ-CORE-120 tranche différemment pour un autre message, en imposant une chaîne
**littérale et anglaise** : « Restaurer un savestate créé par un autre cœur DOIT échouer
avec le message `Save state used a different core.` ». Les deux exigences du même document
emploient donc deux conventions opposées.

La question a un effet observable : le critère d'acceptation de REQ-CORE-011 demande qu'un
en-tête annonçant le mapper 200 produise « un échec avec un message contenant « 200 » », ce
qui est vérifiable dans n'importe quelle langue, mais un vérificateur qui lirait les phrases
de REQ-CORE-011 comme littérales rejetterait une implémentation anglaise.

## Choix provisoire (implémenté dans L1a)

Les phrases de REQ-CORE-011 et REQ-CORE-091 sont traitées comme des **descriptions de
cause**, pas comme des littéraux, et les messages du cœur sont rédigés en **anglais** :

- `Corrupt header: missing iNES signature "NES\x1A".`
- `Corrupt header: a ROM image needs at least 16 bytes, got N.`
- `Corrupt header: the header announces no PRG-ROM.`
- `Truncated file: the header announces N bytes, the image has M.`
- `Unsupported mapper N.`
- `Corrupt savestate: …` (plusieurs variantes selon le champ fautif)

Le message de REQ-CORE-120 est, lui, reproduit **au caractère près** :
`Save state used a different core.`

Justification du choix de l'anglais : c'est la langue du seul message littéral imposé par
SPEC-02, et le cœur est une bibliothèque sans dépendance d'interface (REQ-CORE-001) — la
traduction, si elle est voulue un jour, relève de SPEC-10.

Référencé dans le code par `// Q-001` (`Sen.Nes/Rom/InesHeader.cs`,
`Sen.Nes/Rom/RomImage.cs`, `Sen.Nes/Cartridges/MapperRegistry.cs`,
`Sen.Nes/State/StateReader.cs`, `Sen.Nes/NesCore.cs`).

## Demande à R0

1. Confirmer que seules les chaînes explicitement citées comme littérales (REQ-CORE-120)
   sont normatives, les autres étant des descriptions.
2. Fixer la langue des messages du cœur, ou dire que c'est un choix d'implémentation.
3. Si la langue doit être le français, préciser si les phrases de REQ-CORE-011 sont
   exactement celles à afficher (auquel cas il faudrait aussi traduire REQ-CORE-120, ce qui
   contredirait le texte gelé).

## Réponse R0 (2026-10-20, normative)
Les phrases entre guillemets français de REQ-CORE-011 et REQ-CORE-091 sont des **descriptions de cause**, non des chaînes littérales. Le cœur renvoie une cause typée (code), plus un message technique en anglais. Le texte présenté à l'utilisateur relève de l'hôte (SPEC-07, SPEC-10). Seules les chaînes écrites `en police de code` dans la spec sont littérales (ex. `Save state used a different core.`, `Corrupted save state.`). Le choix provisoire est conforme s'il respecte cette règle.

## Application côté propre (lot L1b, 2026-10-20)
AMD-002 appliqué : le cœur renvoie désormais une **cause typée** en plus du message
technique anglais — `RomLoadFailure` (`CorruptHeader`, `TruncatedFile`,
`UnsupportedMapper`) portée par `RomLoadResult.Failure`, et `StateLoadFailure`
(`CorruptState`, `ForeignCore`) rendue par la surcharge de `TryLoadState`. Le message
littéral `Save state used a different core.` est inchangé. Vérifié par
`tests/Sen.Nes.Tests/Amd002Tests.cs`.

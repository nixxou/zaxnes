# Q-015 — REQ-E3D-450 : l'intervalle `[z⁻, z⁺]` est vide quand `z⁻ > z⁺`

- **Ouvert par** : R3 (côté propre), lot L4b, 2026-10-20
- **Documents concernés** : SPEC-04B REQ-E3D-450 (section pleine enveloppée), REQ-E3D-445
  (paramètres de la section), TV-Y4
- **Classe** : C (ambiguïté de notation)
- **Priorité** : P1 (sans la lecture retenue, 5 092 objets `VCYLINDER` à `fullWarp` des profils
  intégrés perdent une partie de leurs voxels)

## Ambiguïté

REQ-E3D-450 dit :

> Pour chaque point du contour et pour chaque `z ∈ [z⁻, z⁺]` (bornes du point) […]

Or `z⁻ = Cz − z⁺` n'est pas toujours supérieur à `z⁺` : pour un point de **région 2** de petite
ordonnée `q`, `z⁺ = ⌊(Cz + q − 1)/2⌋` est inférieur à `z⁻`. L'intervalle `[z⁻, z⁺]`, lu comme
« de `z⁻` à `z⁺` », est alors vide et ces points ne posent aucun voxel.

TV-Y4 lève le doute. Rangée `1123....`, `D = 4`, `solid = fullWarp = vrai` : `C = 3`, `A = 3`,
`B = 3`, `Cz = 3`. Les trois points de région 2 sont `(3, 0)`, `(3, 1)` et `(3, 2)`, de bornes
`(z⁺, z⁻) = (1, 2)`, `(1, 2)` et `(2, 1)`. Le vecteur attend les voxels `(0, 1)`, `(0, 2)`,
`(3, 1)` et `(3, 2)` : les deux tranches `k = 1` et `k = 2` sont donc bien remplies, y compris
par les points où `z⁺ < z⁻`. L'intervalle se lit « entre les deux bornes », dans les deux sens.

## Choix provisoire

`z` parcourt `[min(z⁻, z⁺), max(z⁻, z⁺)]`, bornes incluses. TV-Y4 passe alors dans ses deux
parties (48 voxels pour la rangée pleine, 12 voxels et 18 rectangles pour `1123....`).

Références dans le code : `Sen.Engine3D.VoxelConstruction.Quadrants` (`// Q-015`). Test :
`CylinderVectorTests.TV_Y4_solid_full_warp_fills_each_column_with_its_own_colour`.

## Question posée à R0

Confirmer la lecture « entre les deux bornes » et reformuler REQ-E3D-450
(« pour chaque `z` entre `z⁻` et `z⁺`, bornes incluses »).

## Réponse R0 (2026-10-20, normative)
Choix provisoire validé : `z` parcourt [min(z⁻, z⁺), max(z⁻, z⁺)], bornes incluses.

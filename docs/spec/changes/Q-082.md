# Q-082 — Profondeur impaire : le point `q = 0` de la région 2 remplit toute la section (cordes de `punchout`, `D = 3`)

Rôle : R3 (côté PROPRE) | Date : 2026-10-31 | Vérification demandée sur les cordes du ring de `punchout`
Documents concernés : `SPEC-04B` `REQ-E3D-444` à `REQ-E3D-452`, §5.3 (`TV-Y1` à `TV-Y8`),
`Q-013`, `Q-014`, `Q-015` (réponse R0 du 2026-10-20).

## 1. Le cas signalé

Profil `assets-neutral/profiles/punchout.bytes`. Le pattern des cordes du ring est le seul
`HCYLINDER` de profondeur 3 du profil : grille 30 × 5 cases, texture personnalisée 240 × 40,
`emptyColor = 4`, `sizeZ = D = 3`, `solid = vrai`, `fullWarp = vrai`, `flip = faux`,
`antiShadow = faux`, `rm = 0` (donc `GREEDY` par les réglages), étiquette `scene`.

Dans cette texture, chaque corde est une ligne horizontale de **2 pixels de haut** (rangées 5–6,
13–14, 21–22) qui court jusqu'au bord droit. `HCYLINDER` découpe ses segments par colonne : dans
chaque colonne d'une corde le segment vaut donc `s = r`, `f = r + 1`, soit **`L = 1`**.

Le relevé fourni indique que, dans le programme original, le maillage d'une telle tuile occupe
**8 × 2 × 1** (une unité de profondeur), alors que Zaxnes produit **8 × 2 × 3**.

## 2. Calcul à la main, d'après `REQ-E3D-444` à `452` seulement

`L = 1`, type plein : `C = s + f = 2r + 1`, `A = L = 1`, `B = min(D − 1, L) = min(2, 1) = 1`,
`Cz = D − 1 = 2`. Ni `A` ni `B` n'est nul : `REQ-E3D-451` ne s'applique pas.

Contour de `REQ-E3D-446` (`A = B = 1`, `A²B² = 1`) :

- région 1 : `(0, 1)` puis `(1, 1)` ; le candidat suivant `(2, 0)` échoue à la rétention
  (`B²p = 2 ≤ A²q = 0` faux) ;
- région 2 : `(1, 0)` puis `(1, 1)` ; le candidat `(0, 2)` échoue (`A²q = 2 ≤ B²p = 0` faux).

Indices de `REQ-E3D-445` (`u⁺ = ⌊(C + p)/2⌋`, `u⁻ = C − u⁺`) :

| point | région | `u⁺` | `u⁻` | `z⁺` | `z⁻` |
|---|---|---|---|---|---|
| `(0, 1)` | 1 | `r` | `r + 1` | `⌊(2 + 1)/2⌋ = 1` | `1` |
| `(1, 1)` | 1 | `r + 1` | `r` | `1` | `1` |
| `(1, 0)` | 2 | `r + 1` | `r` | `⌊(2 + 0 − 1)/2⌋ = 0` | `2` |
| `(1, 1)` | 2 | `r + 1` | `r` | `⌊(2 + 1 − 1)/2⌋ = 1` | `1` |

Le point `(1, 0)` de la région 2 est le seul dont les deux bornes diffèrent, et elles
**encadrent toute la profondeur** : `z⁺ = 0`, `z⁻ = 2`.

Les quatre combinaisons de drapeaux donnent **le même champ de voxels**, les six voxels de la
section complète `2 × 3` (positions dans le plan de la section, `(u, z)`, `u` = rangée d'image) :

```
{ (r, 0), (r, 1), (r, 2), (r + 1, 0), (r + 1, 1), (r + 1, 2) }
```

- `solid = faux` (`REQ-E3D-448`, `fullWarp` sans effet) : les points quadrants du point `(1, 0)`
  sont déjà `(u⁺, 0)`, `(u⁺, 2)`, `(u⁻, 0)`, `(u⁻, 2)` ; les texels affectés sont les rangées
  `r` et `r + 1` de la corde, non nulles, donc tous écrits ;
- `solid = vrai`, `fullWarp = faux` (`REQ-E3D-449`) : depuis `M = (⌊C/2⌋, ⌊Cz/2⌋) = (r, 1)` vers
  `Q0 = (r + 1, 0)`, `Δmaj = 1`, le seul point tracé est `Q0` ; ses quatre miroirs
  `(a, b)`, `(a, Cz − b)`, `(C − a, b)`, `(C − a, Cz − b)` sont `(r+1, 0)`, `(r+1, 2)`,
  `(r, 0)`, `(r, 2)` ;
- `solid = vrai`, `fullWarp = vrai` (`REQ-E3D-450` + `Q-015`) : `z` parcourt
  `[min(z⁻, z⁺), max(z⁻, z⁺)] = [0, 2]`, chaque colonne recevant le texel de sa propre rangée.

Texels pour les drapeaux réels des cordes (`solid = fullWarp = vrai`), en notation §5.3 pour les
types H — `(j, k) →` rangée, avec `j = 7 − y` et une corde en rangées d'image 3 et 4 :

```
(3, 0)→4  (3, 1)→4  (3, 2)→4
(4, 0)→3  (4, 1)→3  (4, 2)→3
```

Profondeur effective de `REQ-E3D-452` pour ce segment : **`D' = B + 1 = 2`** (l'objet entier des
cordes de `punchout` obtient `D' = 3`, car ses autres segments — la foule — atteignent `B = 2`).

Maillage `GREEDY` : une boîte pleine, 6 rectangles ; dans le repère de `REQ-E3D-504`, qui garde
le `D` de construction, `z ∈ [0 − 3/2, 3 − 3/2] = [−1,5 ; 1,5]`, soit **3 unités** de profondeur.
La section d'un cylindre de profondeur impaire n'est donc jamais ronde : elle est pleine.

## 3. Ce que fait Zaxnes

Exactement le calcul ci-dessus, vérifié de deux façons :

- unité, sur le moteur de conversion : `impl/tests/Zax.Engine3D.Tests/CylinderVectorTests.cs`,
  `REQ_E3D_450_a_segment_of_two_pixels_at_depth_three_fills_the_whole_depth` — les six voxels,
  les texels ci-dessus, `D' = 2`, 6 rectangles, boîte locale
  `(−4 ; −1 ; −1,5) … (−3 ; 1 ; 1,5)`, et les mêmes six positions pour les quatre couples de
  drapeaux ;
- sur le profil lui-même : la construction du pattern `HCYLINDER`/`D = 3` de `punchout.bytes`
  donne, pour chaque tuile de corde, 12 triangles et une boîte locale
  `(−4 ; −3 ; −1,5) … (4 ; −1 ; 1,5)` — les `8 × 2 × 3` relevés, `depth = 3` dans
  `render --dump-meshes` étant le `D'` de l'objet entier (`Q-081`).

Aucun écart entre Zaxnes et `REQ-E3D-444` à `452` : **la spécification telle qu'écrite donne bien
une section de 3 unités de profondeur**, et le résultat de 1 unité rapporté pour l'original n'en
découle pas. Aucun code n'a été modifié.

## 4. D'où pourrait venir la section d'une unité

Les deux voxels d'une section d'une seule unité seraient `(r, 1)` et `(r + 1, 1)` : c'est
exactement ce que donne le calcul **si le point `q = 0` de la région 2 n'écrit rien**. Deux
lectures produisent cela ; une seule survit aux vecteurs de §5.3 :

1. **Intervalle vide** quand `z⁻ > z⁺` (la lecture littérale de `REQ-E3D-450` écartée par
   `Q-015`) : elle donnerait bien 1 unité ici, mais elle est **réfutée** par `TV-Y4`
   (`1123....`, `D = 4`), dont les voxels `(0, 1)`, `(0, 2)`, `(3, 1)`, `(3, 2)` ne viennent que
   des points de région 2 `(3, 0)` et `(3, 1)`, tous deux de bornes inversées. Elle ne traite en
   outre pas `solid = faux`, où les voxels de profondeur 0 et 2 sont des points quadrants. La
   réponse R0 de `Q-015` reste donc la seule compatible avec §5.3.
2. **Région 2 démarrant à `(A, 1)`** — autrement dit le premier point `(A, 0)` ne contribuant
   pas. Cette lecture donne 1 unité pour les cordes **et** satisfait les vecteurs :
   - de `q = 0` à `q = 1` la condition de `REQ-E3D-446` est `B²·A(A − 1) > A²B²`, c'est-à-dire
     `A − 1 > A` : toujours fausse. Le premier et le deuxième point de la région 2 partagent
     donc toujours le même `p = A`, donc les mêmes `u⁺`, `u⁻` ;
   - leurs bornes en profondeur ne diffèrent que si `Cz` est **pair**, c'est-à-dire si `D` est
     **impair** : pour `Cz = 2m`, `q = 0` donne `(z⁺, z⁻) = (m − 1, m + 1)` et `q = 1` donne
     `(m, m)` ; pour `Cz = 2m + 1`, les deux donnent `(m, m + 1)` ;
   - or **aucun vecteur de §5.3 n'a de profondeur impaire avec une section non dégénérée** :
     `TV-Y1`, `TV-Y2`, `TV-Y4`, `TV-Y6`, `TV-Y8` et les cas de contrôle utilisent `D = 8`,
     `D = 4` ou `D = 2` ; `TV-Y5` n'a `D = 1` et `D = 5` que dans les cas dégénérés de
     `REQ-E3D-451`. Les vecteurs ne contraignent donc pas ce point.

Les règles `REQ-E3D-445`/`446` telles qu'écrites et cette seconde lecture sont **indiscernables
pour toute profondeur paire** et diffèrent pour toute profondeur impaire. Le relevé des cordes de
`punchout` est le premier cas d'une profondeur impaire observé sur l'original.

## 5. Questions posées

1. `REQ-E3D-446` et `REQ-E3D-445` sont-ils complets pour `D` impair ? Le premier point de la
   région 2, `(A, 0)`, écrit-il bien ses voxels, avec `z⁺ = ⌊(Cz − 1)/2⌋` et `z⁻ = Cz − z⁺` —
   auquel cas le relevé de 1 unité sur les cordes de `punchout` est à revoir — ou la région 2
   démarre-t-elle en pratique à `q = 1` (ou son point `q = 0` est-il sans effet), auquel cas
   `REQ-E3D-446` doit le dire et `Q-015` être précisé en ce sens ?
2. Si la seconde lecture est la bonne, un vecteur de profondeur **impaire** devrait être ajouté à
   §5.3 pour la verrouiller. Le cas discriminant le plus net est une rangée pleine
   `11111111` en `VCYLINDER`, `D = 3` (`A = 7`, `B = 2`, `Cz = 2`) : la région 2 s'y réduit à son
   seul point `(7, 0)` (le candidat `(7, 1)` échoue à la rétention, `A²q = 49 ≤ B²p = 28` étant
   faux). Règles telles qu'écrites → **24 voxels**, les 8 colonnes sur les 3 tranches, soit la
   boîte pleine (ce que Zaxnes produit) ; seconde lecture → **20 voxels**, les colonnes 1 à 6
   pleines mais les colonnes 0 et 7 réduites à la seule tranche médiane `k = 1`, que leur laisse
   le point `(7, 1)` de la région 1. Un différentiel sur l'original lèverait le doute d'un coup.
3. À confirmer de la même façon : la corde de 2 pixels est-elle, dans l'original, de profondeur
   effective `D' = 2` (`REQ-E3D-452`), ce que Zaxnes applique, le maillage restant centré sur
   `D = 3` ?

## 6. Choix provisoire

Aucune modification du moteur : `REQ-E3D-444` à `452` et la réponse R0 de `Q-015` sont appliqués
tels quels, la section d'une corde de 2 pixels à `D = 3` faisant 3 unités de profondeur. Le
vecteur calculé est verrouillé par le test cité au §3 et la conséquence pour les profondeurs
impaires est signalée dans le code par `// Q-082`
(`impl/src/Zax.Engine3D/VoxelConstruction.cs`, à côté du `// Q-015`).

# Q-070 — AMD-029 §2 : valeur exacte de la nouvelle signature de sauvegarde, et nom du cœur

Posée par : R3 (côté propre), lot REN-1 | 2026-10-22 | **Close** — CLOS — choix provisoire de REN-1 adopté (signature ZAXNESAV en écriture, lecture des deux) (R0, 2026-10-23).

## Contexte

AMD-029 §2 impose, pour les sauvegardes d'état :

> L'écriture utilise une nouvelle signature propre au produit. La lecture accepte la nouvelle
> signature **et** l'ancienne (`SEN3DSAV`).

L'amendement donne l'ancienne signature mot pour mot mais **ne donne pas la nouvelle**. Le
format de SPEC-09 §4.5.4 réserve 8 octets à la signature, et `SaveStateFile.MaxFileSize`
(REQ-ARCH-013) borne la taille du fichier à partir de `Signature.Length` : la nouvelle valeur
doit donc faire exactement 8 octets pour que la borne reste celle qui a été vérifiée.

Deux données de format voisines ne sont pas mentionnées par l'amendement :

1. `NesCore.CoreName` (REQ-CORE-120) — « Sen » jusqu'ici — est écrit en tête du **bloc de
   cœur** et relu : un nom inconnu fait refuser la sauvegarde avec
   `Save state used a different core.` ;
2. `NesCore.StateMagic` (`"SEN0"`, un entier 32 bits) ouvre ce même bloc.

Si l'un des deux change sans mesure de compatibilité, une sauvegarde écrite par « Sen » reste
refusée malgré la signature de fichier acceptée, ce qui vide §2 de son effet.

## Choix provisoire

1. **Nouvelle signature** : `ZAXNESAV` (8 octets ASCII), construite comme `SEN3DSAV` l'était —
   le nom du produit puis `AV`. Écriture : `ZAXNESAV`. Lecture : `ZAXNESAV` ou `SEN3DSAV`
   (`SaveStateFile.Signature` / `SaveStateFile.LegacySignature`).
2. **`CoreName`** passe à « Zaxnes », et la lecture accepte en plus l'ancien nom « Sen »
   (`NesCore.LegacyCoreName`), par le même raisonnement que §2 : ce qui est écrit porte le nom
   du produit, ce qui est lu accepte les deux. Un nom qui n'est ni l'un ni l'autre est toujours
   refusé avec le message de REQ-CORE-120, inchangé.
3. **`StateMagic`** reste `"SEN0"` : c'est une donnée de format interne au bloc, du même ordre
   que l'infixe `_3dsen_` des jaquettes que §2 conserve explicitement pour pouvoir relire
   l'existant. La changer n'apporterait rien et casserait la relecture.

Référencé dans le code par `// Q-070` (`SaveStateFile`, `NesCore`).

## Ce qui est demandé à R0

Confirmer la valeur `ZAXNESAV`, ou en imposer une autre de 8 octets ; confirmer les points 2
et 3.

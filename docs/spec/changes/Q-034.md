# Q-034 — La grammaire des clés stables de REQ-PERS-080 interdit les clés `layer[i].offset` de §4.1.6

- Lot : L3 (modèle de réglages et persistance)
- Rôle : R3 (implémenteur, côté propre)
- Date : 2026-10-21
- Documents concernés : SPEC-09 REQ-PERS-080, §4.1.6 (tableau des calques), §4.1.9
  (`input.port_type[0]`, `input.port_type[1]`), REQ-PERS-083

## Ambiguïté

REQ-PERS-080 fixe la forme des clés stables :

> chaque réglage DOIT avoir une clé de la forme `[a-z0-9_]+(\.[a-z0-9_\[\]]+)*`

Dans cette expression, les crochets ne sont admis que dans les segments **qui suivent** un point :
le premier segment est `[a-z0-9_]+`, sans crochet.

Or les tableaux normatifs publient des clés dont le **premier** segment porte des crochets :

- §4.1.6 : `layer[i].offset`, `layer[i].aligned`, `layer[i].coef`, `layer[i].cast_shadow`,
  `layer[i].recv_shadow` — 30 clés dont le premier segment est `layer[i]` ;
- §4.1.9 : `input.port_type[0]` et `input.port_type[1]` sont, eux, conformes (les crochets sont
  dans le second segment).

Les 30 clés de calque ne passent donc pas le critère d'acceptation de REQ-PERS-080 si la
grammaire est appliquée littéralement. Les deux lectures possibles :

1. **les clés publiées font foi** : la grammaire est une coquille, les crochets sont admis dans
   tout segment ; les clés restent `layer[0].offset` … `layer[5].recv_shadow` ;
2. **la grammaire fait foi** : les clés de §4.1.6 doivent être réécrites, par exemple
   `layer.0.offset` ou `layer_0.offset`.

La lecture 2 a un coût : REQ-PERS-080 interdit de renommer une clé publiée, et la correspondance
libretro de REQ-PERS-083 remplace de toute façon `.`, `[` et `]` par `_`, si bien que
`3dsen_layer_3__offset` et `3dsen_layer_3_offset` seraient deux clés d'option différentes selon
la lecture retenue.

## Choix provisoire

**Lecture 1.** Les clés publiées des tableaux §4.1 font foi ; la grammaire est appliquée en
admettant `[` et `]` dans n'importe quel segment, soit
`[a-z0-9_\[\]]+(\.[a-z0-9_\[\]]+)*`. Les 93 clés du modèle valident cette forme et aucune clé de
§4.1 n'est renommée.

Conséquences :

- les clés de calque restent `layer[0].offset` … `layer[5].recv_shadow` ;
- la clé d'option libretro correspondante serait `3dsen_layer_3__offset` (deux soulignés, de
  `[3]`), mais les calques ne sont **pas** exposés en libretro (§4.1.6, dernière phrase), donc
  aucune option publique ne dépend de ce choix ;
- la liste de référence versionnée du critère d'acceptation de REQ-PERS-080 est
  `tests/Sen.Settings.Tests/SettingKeys.reference.txt`.

Référencé dans le code par `// Q-034` (`src/Sen.Settings/SettingDescriptor.cs`,
`IsValidKey`), couvert par `tests/Sen.Settings.Tests/CatalogueTests.cs`
(`Keys_are_stable_and_unique`, `No_published_key_disappeared`).

## Question pour R0

Confirmer que les clés publiées de §4.1.6 l'emportent et que la grammaire de REQ-PERS-080 doit
être corrigée en `[a-z0-9_\[\]]+(\.[a-z0-9_\[\]]+)*`, ou bien fixer la forme de remplacement des
30 clés de calque avant toute publication.

## Réponse R0 (2026-10-21, normative)
Choix provisoire validé.

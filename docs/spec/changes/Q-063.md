# Q-063 — `REQ-E3D-512` est citée mais n'existe pas

**Ouvert par** : R3, implémenteur, côté propre
**Date** : 2026-10-21 (phase P6, clôture)
**Document concerné** : `SPEC-04B-geometrie.md`, REQ-E3D-406
**Priorité** : P3 — défaut de documentation, **sans effet sur l'implémentation**
**Statut** : signalé ; aucune correction appliquée (les fichiers `SPEC-*.md` sont gelés)

## 1. Le fait

REQ-E3D-406 commence par :

> La position scène d'un point `v` du maillage local d'une tuile (REQ-E3D-504, **REQ-E3D-512**)
> DOIT être `P = Pos + R · (S ⊙ (T + (0, 0, n) − Pos + v + δ))` …

**REQ-E3D-512 n'est définie nulle part**, ni dans SPEC-04B, ni dans un autre document, ni dans
un amendement. Les exigences de SPEC-04B voisines de ce numéro sont REQ-E3D-500 à REQ-E3D-507
(maillage local d'une tuile) puis REQ-E3D-520 à REQ-E3D-524 (maillage MARCHING) ; il n'y a aucune
exigence entre -507 et -520. La seule occurrence de `REQ-E3D-512` dans tout `spec/` est cette
citation.

Relevé par le contrôle de couverture de la matrice de traçabilité de la phase P6
(`impl/tools/traceability-check.ps1`, rapport `spec/TRACEABILITY-CHECK-P6.md`) : c'est le seul
identifiant de la spécification qui n'a pas de ligne dans `verify/round1/traceability.csv`, et
c'est normal — ce n'est pas une exigence.

## 2. L'ambiguïté

Le renvoi veut désigner « le maillage local d'une tuile ». REQ-E3D-504 en fait partie. Le second
renvoi visait vraisemblablement soit REQ-E3D-520 à -524 (le maillage que produit l'autre
algorithme, dont les sommets passent par la même transformation), soit un numéro de la série -500
à -507. Les deux lectures donnent **la même règle de transformation** : REQ-E3D-406 ne dépend du
renvoi que pour dire d'où vient `v`, et `v` est un sommet du maillage local quel que soit
l'algorithme qui l'a produit.

## 3. Le choix provisoire de l'implémenteur

Le renvoi est lu comme **« le maillage local d'une tuile, quel qu'en soit l'algorithme »** :
REQ-E3D-406 s'applique aux sommets produits par REQ-E3D-500 à -507 (greedy et multicolore) comme
à ceux produits par REQ-E3D-520 à -524 (MARCHING). C'est déjà ce que fait l'implémentation depuis
le lot L4b, et c'est ce que le round 1 a vérifié CONFORME pour REQ-E3D-406 : la transformation de
scène est appliquée dans `src/Sen.Engine3D/GeometryBuilder.cs` et
`src/Sen.Render/SceneRenderer.cs` indépendamment du mailleur utilisé.

**Aucune modification de code n'est nécessaire** ; aucune référence `// Q-063` n'est donc posée.
La seule demande est documentaire : si une version ultérieure de SPEC-04B est ouverte, remplacer
« REQ-E3D-512 » par le bon renvoi ou par « REQ-E3D-500 à -507 et REQ-E3D-520 à -524 ».

## 4. Référence en code

Aucune.

## Réponse R0 (2026-10-21, normative)
Erratum documentaire : le renvoi à `REQ-E3D-512` est caduc et sans effet normatif ; il est ignoré.

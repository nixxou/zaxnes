# Q-065 — Quelle entrée « 2D Mode » quand il n'y a plus de catalogue embarqué ?

**Ouvert par** : R3, implémenteur, côté propre
**Date** : 2026-10-21 (phase P7, lot P7a)
**Documents concernés** : `changes/AMD-024-p7-assets-libres.md` REQ-PUB-001,
`SPEC-03-format-profil.md` REQ-PROF-060/061, `SPEC-06-scene-rendu.md` REQ-SCN-055
**Priorité** : P1 — sans réponse, le mode 2D disparaît de la version publiable
**Statut** : choix provisoire appliqué, référencé `// Q-065` dans le code

## 1. L'ambiguïté

REQ-PUB-001 exige que l'application soit « pleinement utilisable sans le dossier
`assets-neutral` », **mode 2D compris**. L'inventaire P7.1 le répète : « L'application fonctionne
sans profil : géométrie par défaut en 3D, et mode 2D. »

Or le mode 2D n'est pas un chemin de rendu : REQ-SCN-055 le définit comme **le profil embarqué
spécial intitulé « 2D Mode », fichier `profiles/empty.bytes`**, et REQ-PROF-060 le liste comme
l'entrée d'`id` `"47"` du catalogue `profiles.json`. Les deux fichiers sont retirés de la version
publiable (REQ-PUB-002). Sans eux, la bibliothèque n'a aucune entrée « 2D Mode » et
`--profile` n'a plus rien à résoudre : le mode 2D serait inaccessible, ce que REQ-PUB-001
interdit.

AMD-024 ne dit pas comment reconstituer l'entrée. Deux lectures :

- **(A)** « bibliothèque vide » au sens strict : aucune entrée, pas même « 2D Mode ». Le mode 2D
  ne serait alors accessible que par la bascule à chaud F11 d'AMD-017 (Q-037), donc uniquement
  **après** avoir lancé une ROM par un autre chemin — et REQ-PUB-001 ne serait pas satisfaite au
  sens de « mode 2D » comme entrée de bibliothèque.
- **(B)** La bibliothèque ne contient aucun **profil de jeu**, mais l'entrée générique
  « 2D Mode » est **fabriquée par le code**, puisque son profil n'a par définition aucun motif :
  c'est le profil vide, que `GameProfile.CreateEmpty()` produit déjà.

## 2. Le choix provisoire de l'implémenteur

**Lecture (B).** Le catalogue embarqué devient une constante du code
(`BuiltInCatalogue`, `src/Sen.Profiles/Catalogue/BuiltInCatalogue.cs`) qui ne contient **qu'une
entrée** : `id = "47"`, `title = "2D Mode"`, sans fichier. Son profil n'est pas lu sur disque :
c'est `GameProfile.CreateEmpty()`.

Justification des deux valeurs reprises de la spec :

- l'`id` `"47"` et le titre `"2D Mode"` sont écrits en clair dans REQ-PROF-060 et REQ-PROF-061 :
  ce sont des **données d'interopérabilité**, au même titre que la clé d'encodage des tuiles de
  REQ-PUB-007. Garder l'`id` d'origine fait qu'un `library.json` ou un `games.json` écrit par une
  version antérieure continue de retrouver son entrée 2D (REQ-PERS-035) ;
- aucun autre champ du catalogue n'est repris : éditeur, description et auteur sont vides, et les
  100 autres entrées disparaissent.

Les réglages du profil vide sont ceux de REQ-PROF-040 et le clipping par défaut de REQ-SCN-003,
`(0,1 ; 8,1 ; 8,1 ; 0,1)` — **et non** le `(4,1 ; 16,1 ; 4,1 ; 0,1)` que le critère de
REQ-PROF-041 relève dans `empty.bytes`, qui est une valeur du fichier d'origine et non une donnée
d'interopérabilité. Le cadrage du mode 2D de la version publiable diffère donc légèrement de celui
de l'original : **divergence D**, dans le prolongement d'AMD-024.

Le mode `--assets <dossier>` continue de lire un `profiles.json` fourni par l'utilisateur ; les
101 entrées reviennent alors telles quelles, l'entrée « 2D Mode » du catalogue lu remplaçant celle
du code.

## 3. Référence en code

- `src/Sen.Profiles/Catalogue/BuiltInCatalogue.cs` — le catalogue d'une entrée.
- `src/Sen.App/LibraryGameCatalog.cs`, `src/Sen.App/ProfileResolver.cs` — son emploi quand il n'y
  a pas de dossier d'assets.
- `tests/Sen.App.Tests/AssetFreeStartupTests.cs` — le mode 2D sans dossier d'assets.

La réponse R0 ajoute une seconde entrée générique, « 3D par défaut (sans profil) », qui convertit n'importe quelle ROM avec la géométrie par défaut ; elle est implémentée avec un identifiant propre au projet (`"3d"`) et l'override 2D/3D de `GameSession.Create`.

## Réponse R0 (2026-10-21, normative)
« 2D Mode » est une **entrée intégrée générée par le code**, sans fichier, toujours proposée dans la sélection de profil (en tête de liste) et utilisée par défaut quand l'utilisateur ne choisit rien. Les autres entrées sont les profils `.3dn` importés et l'option « 3D par défaut (sans profil) ».

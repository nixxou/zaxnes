# Q-008 — Dossier des profils utilisateur : `CustomProfiles` ou `profiles` ?

- **Ouvert par** : R3 (côté propre), lot L2, 2026-10-20
- **Documents concernés** : SPEC-03 REQ-PROF-062, REQ-PROF-063 ; SPEC-09 REQ-PERS-040,
  REQ-PERS-041, REQ-PERS-072 (tableau de disposition de la racine utilisateur)
- **Classe** : C (contradiction entre deux specs)
- **Priorité** : P2 (aucun effet sur le format ni sur l'émulation ; effet sur l'emplacement
  où l'utilisateur dépose ses `.3dn`)

## Contradiction

Les deux documents nomment différemment le même dossier :

- **SPEC-03 REQ-PROF-062** : « tous les fichiers `*.3dn` du dossier **`CustomProfiles`** situé
  dans le dossier de données de l'utilisateur (SPEC-09) sont examinés ». Le renvoi à SPEC-09
  laisse entendre que SPEC-09 fixe le nom.
- **SPEC-09 REQ-PERS-072** : le tableau normatif de la racine utilisateur porte
  **`profiles/*.3dn`** — « profils utilisateur importés ». REQ-PERS-040 parle du « dossier des
  profils utilisateur (`profiles/` de la racine utilisateur) ».

`CustomProfiles` est le nom **observé dans l'original** (SPEC-09 §4.4, section explicitement
informative, qui liste `CustomProfiles\*.3dn` sous la racine
`AppData\LocalLow\Geod Studio\3dSen\`). `profiles` est le nom que SPEC-09 §3.8 fixe pour la
réimplémentation, dont la racine est de toute façon différente (`%LOCALAPPDATA%\Sen`,
DEC-09-Q7).

La lecture la plus cohérente est donc : REQ-PROF-062 décrit l'original, et le nom normatif pour
la reconstruction est celui de REQ-PERS-072. Mais REQ-PROF-062 est rédigée au présent normatif
(« DOIVENT être examinés ») et nomme `CustomProfiles` sans dire qu'il s'agit du nom d'origine,
d'où la question.

## Choix provisoire

Le dossier est **`profiles`** (SPEC-09 REQ-PERS-072, qui est le seul tableau normatif de la
disposition de la réimplémentation). Comme aucune donnée livrée n'en dépend, le nom est un
**paramètre** : `UserDataLayout(root, profilesFolderName = "profiles")`, ce qui permet de passer
`"CustomProfiles"` si R0 tranche dans l'autre sens, sans toucher au reste du code.

Références dans le code : `Sen.Profiles.Catalogue.UserDataLayout` (`// Q-008`),
`Sen.Profiles.Catalogue.UserProfileFolder`. Tests :
`CatalogueAndLibraryTests.REQ_ARCH_033_the_user_data_layout_is_built_from_an_injected_root`.

## Question posée à R0

Confirmer `profiles` pour la reconstruction, ou imposer `CustomProfiles` (fidélité au nom
d'origine, utile si un utilisateur recopie son ancien dossier). Préciser, le cas échéant, s'il
faut lire les deux dossiers (migration douce) au premier lancement.

## Réponse R0 (2026-10-20, normative)
Choix provisoire validé : dossier des profils utilisateur `profiles/` sous la racine utilisateur (SPEC-09 REQ-PERS-072 fait foi pour la reconstruction). `CustomProfiles` est le nom observé dans l'original ; un import depuis ce dossier PEUT être proposé.

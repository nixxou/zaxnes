# Q-038 — Contenu du sous-menu « Mode caméra » d'AMD-010

- Lot : L9 (interface d'émulateur classique)
- Rôle : R3 (implémenteur, côté propre)
- Date : 2026-10-21
- Documents concernés : AMD-010 REQ-UI-200 (menu **Vidéo**, entrée « Mode caméra ▸ ») ;
  SPEC-06 REQ-SCN-006 (modes TPV et FPV), REQ-SCN-009 (caméra locale), REQ-SCN-021 ;
  SPEC-09 §4.1.2 (`camera.local_cam`, portée P)

## Ambiguïté

Le menu **Vidéo** de REQ-UI-200 contient « Mode caméra ▸ », avec un triangle de sous-menu, mais
l'amendement n'en énumère pas les entrées, et SPEC-10 n'a pas de contrôle équivalent : son
onglet SETTING (REQ-UI-061) ne montre aucun réglage de caméra autre que `FOV`.

SPEC-06 offre deux candidats, qui ne sont pas la même chose :

1. le **mode** de REQ-SCN-006 : TPV = 0 (vue orbitale autour de l'écran NES, défaut) et FPV = 1
   (vue qui suit un personnage), chacun avec son jeu de consignes, un changement ouvrant une
   fenêtre de transition de 3 s ;
2. la **caméra locale** de REQ-SCN-009 (`Setting.LocalCam`, alias `TopDownCam`), un réglage
   booléen de **portée P** qui change la composition de la rotation dans les deux modes.

L'entrée pourrait donc désigner l'un, l'autre, ou les deux. Le cas de la caméra locale est en
outre délicat : c'est un réglage que le **profil** fournit (REQ-PERS-005 point 1), donc une
modification faite au menu est écrasée au chargement d'un jeu différent.

Un troisième point n'est pas tranché : REQ-SCN-021 fait entrer en FPV avec une **shape suivie**,
que seul un script Lua peut désigner. Une entrée de menu ne peut qu'appeler le changement de mode
nu (`Camera:SetFPV()` sans argument), qui laisse la cible où elle est.

## Choix provisoire

Le sous-menu réunit **les deux**, dans cet ordre :

- « Orbitale (TPV) » et « Première personne (FPV) », deux entrées exclusives qui reflètent et
  fixent le mode de REQ-SCN-006. Le changement de mode est le changement nu : la cible courante
  est conservée et la fenêtre de transition de 3 s de REQ-SCN-020 s'ouvre normalement ;
- un séparateur, puis « Vue de dessus », une case à cocher sur `camera.local_cam`.

Conséquences assumées :

- « Vue de dessus » étant de portée P, la coche revient à la valeur du profil au chargement d'un
  jeu différent, comme tout réglage de portée P modifié depuis l'interface. Aucune mention n'est
  faite à l'utilisateur, la fenêtre d'options signalant déjà ce statut pour les réglages
  concernés ;
- entrer en FPV depuis le menu sans shape suivie donne une vue dont la cible ne bouge pas, ce qui
  est le comportement de `Camera:SetFPV()` sans argument (REQ-SCN-021) ;
- les deux entrées de mode sont inactives pendant un chargement, comme les autres commandes
  (REQ-LOOP-007).

Référencé dans le code par `// Q-038` (`src/Sen.App/Ui/MenuBarModel.cs`, `CameraItems`), couvert
par `tests/Sen.App.Tests/MenuBarTests.cs`
(`REQ_UI_200_every_entry_of_the_table_exists_and_names_a_command`).

## Question pour R0

1. Confirmer que « Mode caméra » couvre les deux notions, ou bien réduire l'entrée au seul mode
   TPV/FPV et sortir « Vue de dessus » du menu.
2. Confirmer qu'un réglage de **portée P** peut être modifié depuis le menu, sachant qu'il sera
   remplacé au chargement d'un jeu différent.

## Réponse R0 (2026-10-21, normative)
Choix provisoire validé.

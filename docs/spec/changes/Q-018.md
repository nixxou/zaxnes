# Q-018 — Annexe A compte 42 objets `_gaxis`, REQ-E3D-407 n'en reconnaît que 41

- **Ouvert par** : R3 (côté propre), lot L4b, 2026-10-20
- **Documents concernés** : SPEC-04B annexe A (ligne « étiquettes `!cast` / `!receiv` /
  `!recv` / `_gaxis` : 980 / 160 / 406 / 42 »), REQ-E3D-407 (ordre des rotations),
  REQ-E3D-567 (étiquettes d'ombre) ; SPEC-03 (champ 20, `TagStr`)
- **Classe** : B (chiffre d'annexe obtenu par une mesure différente de la règle normative)
- **Priorité** : P3 (un objet, dans « Road Fighter (Japan) »)

## Écart

REQ-E3D-407 définit l'étiquette comme un élément de la liste :

> si les étiquettes de l'objet (`TagStr`, liste séparée par des **virgules**, espaces de bord
> ignorés) contiennent `_gaxis`, alors `R = Ry(ry) · Rx(rx) · Rz(rz)`

Mesure côté propre sur les 101 profils de `assets-neutral/profiles` : le texte `_gaxis`
apparaît dans **42** chaînes `TagStr`, réparties sur 7 profils, ce qui est bien le chiffre de
l'annexe. Mais l'une de ces chaînes est `mc._gaxis` (« Road Fighter (Japan) ») : découpée sur
les virgules, elle donne une étiquette unique `mc._gaxis`, qui n'est pas `_gaxis`. Le nombre
d'objets dont la **liste d'étiquettes** contient `_gaxis` est donc **41**.

Détail des 42 occurrences :

| Profil | Occurrences | Chaînes |
|---|---|---|
| City Connection | 28 | `vcar,_gaxis` ×26, `rjeep,_gaxis`, `_gaxis` |
| Donkey Kong | 4 | `_gaxis` ×4 |
| Spy Hunter (U) | 4 | `rot,_gaxis` ×4 |
| Super Mario Bros 3 (U) (PRG1) | 2 | `_gaxis` ×2 |
| Road Fighter (Japan) | 2 | `rjeep,_gaxis`, **`mc._gaxis`** |
| Jackal (U) | 1 | `!cast,_gaxis` |
| Micro Mages | 1 | `_gaxis` |

La version publique antérieure du moteur teste l'appartenance exacte à la liste
(`third_party/3DNes_Engine`, `Pattern3D.ContainsTag` → `List<string>.Contains(value)`), donc 41
pour elle aussi. La même question se poserait pour `!cast`, `!receiv`, `!recv` et pour les
liaisons de scripts (SPEC-05), mais aucune autre chaîne des profils intégrés ne contient une de
ces étiquettes en sous-chaîne d'un autre mot : les trois autres chiffres de l'annexe (980, 160,
406) sont identiques dans les deux mesures.

## Choix provisoire

REQ-E3D-407 fait foi : l'étiquette doit être un élément de la liste séparée par des virgules,
espaces de bord retirés. L'objet `mc._gaxis` de « Road Fighter (Japan) » garde donc l'ordre de
rotation par défaut `Rx · Ry · Rz`. Le test du côté propre vérifie les deux nombres (42
occurrences du texte, 41 étiquettes), ce qui garde la trace de l'écart.

Références dans le code : `Sen.Engine3D.DrawListBuilder.RotationOf` (`// Q-018`),
`Sen.Engine3D.PatternInstance.HasTag`. Test :
`GeometryCorpusTests.Annex_A_every_object_of_the_101_profiles_builds_and_the_counts_match`.

## Question posée à R0

Confirmer l'appartenance exacte à la liste et corriger le chiffre de l'annexe A (42 occurrences
du texte, 41 étiquettes effectives), ou bien, si l'original teste la sous-chaîne
(`TagStr.Contains`), le dire dans REQ-E3D-407 et REQ-E3D-567 — l'étiquette `!recv` serait alors
aussi reconnue dans `!receiv`, ce qui changerait le compte des ombres reçues.

## Réponse R0 (2026-10-20, normative)
Confirmé : l'étiquette est un élément exact de la liste séparée par des virgules (41 objets). L'annexe A compte des occurrences de texte (42) ; REQ-E3D-407 fait foi.

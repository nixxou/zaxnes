# Q-031 — Région automatique contre `TVMode` du profil : le réglage utilisateur est toujours écrasé

- **Ouvert par** : R3 (côté propre), lot L6, 2026-10-21
- **Documents concernés** : SPEC-07 REQ-LOOP-017 (P1) et son critère d'acceptation
  (« région automatique active, charger une ROM marquée PAL → réglage région = PAL et cadence
  50 Hz ») ; DEC-03-Q01 (« détection automatique de la région depuis la ROM, **puis**
  application du `TVMode` du profil au chargement d'un jeu différent (fidèle) ») ;
  DEC-09-Q1 (`TVMode` reste porté par le profil) ; SPEC-09 §4.1.7, portée **P** de
  `emu.tv_mode` et renvoi « voir Q-1 pour l'ordre avec le profil » ;
  SPEC-03 REQ-PROF-041 (liste des réglages P embarqués)
- **Classe** : D (ordre modifié dans un cas)
- **Priorité** : P1 (REQ-LOOP-017 est P1 et porte un critère exécutable)

## Contradiction

Les deux règles sont claires séparément et incompatibles ensemble :

- DEC-03-Q01 fixe l'ordre **détection ROM → `TVMode` du profil** au chargement d'un jeu
  différent. Comme `emu.tv_mode` est de portée P, le profil a donc toujours le dernier mot.
- Or **tout profil embarqué porte un message de réglages** (SPEC-03 REQ-PROF-041), donc une
  valeur de `TVMode`, le plus souvent NTSC. Appliquer littéralement DEC-03-Q01 rend le réglage
  `emu.auto_tv_mode` sans **aucun** effet observable : la région détectée est écrasée à la
  frame suivante par celle du profil.
- Le critère d'acceptation de REQ-LOOP-017 est alors infalsifiable : il ne peut passer que si
  le profil déclare lui-même PAL, c'est-à-dire précisément quand la détection ne sert à rien.

Vérifié dans la reconstruction : avec l'ordre littéral de DEC-03-Q01, une ROM dont l'en-tête
porte `byte 9 bit 0 = 1` (PAL) et un profil `TVMode = NTSC` donne une cadence de 60 Hz avec
« région automatique » cochée.

## Choix provisoire

`EmulationHost.ApplyRegionOnLoad` :

1. **région automatique inactive** (défaut, REQ-PERS-002) : ordre fidèle de DEC-03-Q01 —
   détection de la région depuis l'en-tête puis application du `TVMode` du profil quand le jeu
   change ou qu'il s'agit de « 2D Mode ». C'est ce qu'une session normale voit ;
2. **région automatique active** : la région détectée est appliquée et le `TVMode` du profil
   **n'est pas** appliqué, ce qui rend le critère de REQ-LOOP-017 vérifiable et donne un sens
   au réglage ;
3. un changement de région en cours de partie est appliqué immédiatement au cœur et à la
   cadence dans les deux cas (REQ-LOOP-017, dernière phrase).

Référencé `// Q-031` dans `EmulationHost.ApplyRegionOnLoad`. Testé par
`EmulationStateMachineTests.REQ_LOOP_017_automatic_region_follows_the_rom_header`.

## Question posée à R0

1. Confirmer le point 2, ou bien amender REQ-LOOP-017 en indiquant que son critère ne vaut que
   pour un profil sans message de réglages exploitable (et que `emu.auto_tv_mode` est alors
   sans effet pour les 101 profils embarqués — ce qui mériterait d'être écrit).
2. Préciser, dans les deux cas, ce que devient `emu.tv_mode` **persisté** : étant de portée P
   il n'est pas écrit dans `settings.json` par la reconstruction, alors que l'original l'y
   écrit sans effet (SPEC-09 §2, portée P). La reconstruction ne le persiste pas.

## Réponse R0 (2026-10-21, normative)
Choix provisoire validé.

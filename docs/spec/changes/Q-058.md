# Q-058 — Tests d'acceptation à mettre à jour après AMD-021

- **Ouvert par** : R3 (côté propre), lot R2-fixes, 2026-10-21
- **Documents concernés** : `spec/changes/AMD-021-round2.md` §4.1 (remplacements déclarés) ;
  `impl/tests/Acceptance/` (propriété de R4)
- **Classe** : E (tests de la vérification encodant une règle remplacée ; aucune ambiguïté de
  spec)
- **Priorité** : P1 (le gate de REQ-ACC-050 compte ces échecs)

## Écart

L'implémentation d'AMD-021 est faite ; trois tests d'acceptation de `impl/tests/Acceptance/`
encodent des règles que §4.1 d'AMD-021 déclare remplacées et échouent donc désormais. La
consigne du lot interdit de les modifier côté implémenteur : ils sont listés ici pour R4, avec la
ligne de §4.1 qui les supersède et la valeur que la règle nouvelle produit.

Relevé : `dotnet test -c Release` → 3 081 tests passés, 3 ignorés (ROM publiques absentes) et
**ces 3 échecs**, tous dans `Sen.Acceptance.Tests`.

| Fichier, ligne | Test | Ligne de §4.1 qui supersède | Assertion en cause → valeur sous AMD-021 |
|---|---|---|---|
| `tests/Acceptance/InputCoreTests.cs:273` | `REQ_INP_030_the_digital_threshold_is_zero_point_thirty_four` | « AMD-020 (Q-048, course brute) → R2-011 (valeur mise en forme) » | `HalfAxis(-0,30 ; 0 ; −1) == 0,30` → **0,142857** (c'est l'échec constaté), puis `HalfAxis(-0,40 ; 0 ; −1) == 0,40` → **0,285714**. Le vecteur du critère change aussi : R2-011 donne « 0,40 → pas d'appui ; 0,45 → appui », donc `Sample(…).HasFlag(RotLeft)` est **faux** à −0,30, −0,34 et −0,40, et vrai à partir de −0,438. La gâchette à 0,5 reste `ZoomIn` enfoncé (0,429 ≥ 0,34), et `IsPressed(0,33999)` / `IsPressed(0,34)` restent faux / vrai. |
| `tests/Acceptance/InputCoreTests.cs:304` | `REQ_INP_031_the_dead_zones_are_the_documented_ones` | « REQ-INP-031 : zone morte de gâchette 0,1 → R2-011 : zone morte de gâchette 0,2 » | `TriggerDeadZone == 0,1f` → **0,2** (échec constaté : attendu 0,1, obtenu 0,2). Le reste du test passe : `Trigger(0,1) == 0`, `Trigger(1) == 1` (saturation 0,9), et toutes les assertions sur le stick. À ajouter si R4 le souhaite : `TriggerSaturation == 0,9`. |
| `tests/Acceptance/CoreZapperAudioTests.cs:66` | `The_zapper_byte_follows_the_trigger_bit_and_the_light_bit` | « Réponse à Q-005, point 1 (« les enregistrements restent lisibles pendant le vblank ») et note de REQ-CORE-062 → R2-006 » | La lecture de `$4017` est faite après deux `RunFrame`, c'est-à-dire **pendant le vblank**, où R2-006 ne fait plus voir que l'arrière-plan universel. Avec `$3F00 = $0F` (noir) la lumière n'est plus vue : l'octet attendu devient **`0x08`** (échec constaté : attendu 0, obtenu 8). Pour garder `0x00`, il suffit d'écrire un arrière-plan universel clair (`$3F00 = $30`), ce que fait le critère (a) ajouté par §4.2 à R2-006 ; c'est la forme retenue par le test unitaire correspondant, `Sen.Nes.Tests.ZapperTests.AMD_021_R2_006_a_vblank_read_sees_only_the_universal_backdrop`. |

Trois autres tests cités comme candidats par la consigne du lot **passent sans changement** et
ne demandent rien :

- `CoreZapperAudioTests.Exactly_nine_colours_are_dark` : il lit `$3F00` sur un écran où le fond
  universel est précisément la couleur testée, donc la règle de R2-006 donne le même verdict.
- `CoreZapperAudioTests.An_off_screen_aim_never_sees_light` et
  `Light_appears_only_once_the_scan_has_passed_the_pixel` : la condition 1 de REQ-CORE-062
  (0 ≤ x < 256, 0 ≤ y < 240) est inchangée, et la seconde lit `x = 103 < 239` en plein balayage.
- `SceneRenderTests.Each_TV_box_setting_names_its_meshes` : il n'affirme rien sur la constante
  d'albédo, donc le passage de 0,21 à 0,208 (§4.1) ne le touche pas.
- `tests/Acceptance/AudioTests.cs` : aucun test n'affirme qu'un réglage donné de la page
  Réglages joue un son, donc R2-013 ne casse rien ; l'observable est maintenant
  `OptionsModel.PlaysValidationSound` et `AudioMixer.SoundsPlayed`.

## Choix provisoires

Aucun : rien n'est ambigu. Les tests de `tests/Sen.Nes.Tests/`, `tests/Sen.App.Tests/`,
`tests/Sen.Engine3D.Tests/` et `tests/Sen.Render.Tests/` qui portaient les mêmes règles ont été
mis à jour côté implémenteur, et un test a été ajouté pour chaque critère d'acceptation nouveau
de §1 et de §4.2.

## Question posée à R0 / R4

Mettre à jour les trois tests ci-dessus. Aucune modification de spec n'est demandée.

## Réponse R0 (2026-10-21, normative)
Confirmé : les trois tests d'acceptation listés encodent des règles remplacées par AMD-021 §4.1 ; le vérificateur les met à jour aux nouvelles valeurs.

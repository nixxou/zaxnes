# Q-037 — Ce que fait « Mode 3D / Mode 2D » et comment on revient en 3D

- Lot : L9 (interface d'émulateur classique)
- Rôle : R3 (implémenteur, côté propre)
- Date : 2026-10-21
- Documents concernés : AMD-010 REQ-UI-200 (menu **Vidéo**, entrée « Mode 3D / Mode 2D »),
  REQ-UI-204 (raccourci `F11`), REQ-UI-201 ; SPEC-03 (entrée « 2D Mode » du catalogue),
  SPEC-06 REQ-SCN-055, SPEC-10 §2

## Ambiguïté

AMD-010 REQ-UI-200 inscrit « Mode 3D / Mode 2D » dans le menu **Vidéo** et REQ-UI-204 lui donne
le raccourci `F11`, mais aucun des deux ne dit ce que l'entrée **fait**.

Le mode 2D n'est pas un réglage dans la spec gelée : c'est une **entrée de bibliothèque**.
SPEC-10 §2 la décrit comme « entrée spéciale du catalogue qui joue sans conversion 3D », SPEC-03
la fournit dans le catalogue intégré et REQ-SCN-055 fixe son rendu. Il n'existe ni réglage
`video.two_d`, ni commande de SPEC-07 qui éteindrait la conversion en cours de partie : jouer en
2D, c'est **lancer la ROM sur l'entrée « 2D Mode »** plutôt que sur un profil 3D.

Une bascule a donc deux effets que la spec ne tranche pas :

1. **le jeu redémarre** (REQ-LOOP-021 : un lancement est un démarrage à froid), ce qui n'est pas
   ce qu'« une bascule » suggère ;
2. **le retour en 3D a besoin de savoir vers quel profil revenir**. Depuis le mode 2D, le profil
   3D de la ROM n'est plus celui du jeu courant, et REQ-UI-201 mémorise « le » profil choisi pour
   ce fichier — qui vient justement d'être remplacé par « 2D Mode ».

Lectures possibles :

1. l'entrée n'est pas une bascule mais un raccourci vers « 2D Mode » seulement, le retour se
   faisant par « Choisir le profil 3D… » ;
2. l'entrée est une vraie bascule, et le retour utilise un profil mémorisé spécialement pour
   cela ;
3. l'entrée bascule un réglage de rendu qui désactiverait la conversion sans relancer — ce que
   ni SPEC-06 ni SPEC-07 ne prévoient.

La lecture 3 est à écarter : elle demanderait un réglage et un chemin de rendu que la spec gelée
ne décrit nulle part, et elle ne produirait pas les patterns appris que REQ-SCN-055 attend du
mode 2D.

## Choix provisoire

**Lecture 2, avec une mémoire de session.**

- l'entrée relance la **ROM courante** sur l'autre entrée : depuis un profil 3D vers « 2D Mode »,
  et depuis « 2D Mode » vers le profil 3D d'où la session vient ;
- avant de passer en 2D, le profil 3D courant est retenu **en mémoire, pour ce fichier de ROM**,
  le temps de la session. Il n'est pas écrit dans `games.json` ;
- `games.json` enregistre, lui, le choix effectif : après un passage en 2D, rouvrir ce fichier
  plus tard le rouvre **en 2D**, ce qui est bien « le choix mémorisé pour ce fichier » de
  REQ-UI-201 ;
- si le programme a été relancé depuis, ou si la ROM a été ouverte directement en « 2D Mode », il
  n'y a pas de profil de retour : l'entrée ouvre alors la **sélection de profil** de REQ-UI-201,
  qui est la seule information manquante ;
- sans jeu chargé, l'entrée affiche une notification et ne fait rien.

## Question pour R0

1. Confirmer que l'entrée relance le jeu, ou bien préciser qu'elle doit être un simple raccourci
   vers « 2D Mode » (lecture 1).
2. Confirmer que le passage en 2D **écrase** le choix mémorisé du fichier dans `games.json`, ou
   bien demander que le profil 3D reste le choix persistant et que le mode 2D ne vaille que pour
   la session.

## Réponse R0 (2026-10-21, normative, remplace le choix provisoire)
« Mode 3D / Mode 2D » (F11) est une **bascule à chaud du rendu**, sans relancer la ROM ni perdre la partie : en mode 2D, la vue affiche l'image en pixels du cœur sur le plan NES (AMD-009) ; en revenant en 3D, le rendu 3D du profil courant reprend immédiatement. Le profil, l'état du jeu, les scripts et la conversion ne sont pas réinitialisés. L'entrée de bibliothèque « 2D Mode » reste disponible dans la sélection de profil pour les ROM sans profil. **(D)**

# Q-074 — Supprimer un jeu dont le profil est dans le dossier du programme

- **Ouvert par** : R3 (côté propre), lot FEAT-1, 2026-10-23
- **Documents concernés** : AMD-033 §1 et §2 (dossier `profiles` à côté de l'exécutable,
  lecture seule), SPEC-03 REQ-PROF-065 (supprimer un jeu supprime son fichier `.3dn`),
  SPEC-10 REQ-UI-037 (« Supprimer le jeu » n'est offert que pour un profil utilisateur)
- **Classe** : A (cas non traité : deux exigences vraies séparément, sans règle pour leur
  intersection)
- **Priorité** : P3 (une action de menu sur un cas nouveau ; rien n'est perdu dans aucun choix)
- **Statut** : CLOS — choix provisoire adopté : un jeu venant du dossier du programme ne peut pas être supprimé depuis Zaxnes (R0, 2026-10-23).

## Écart

AMD-033 fait apparaître dans la bibliothèque des profils qui ne sont **pas** des profils
intégrés — ils ont la même nature que les profils importés, donc `Source = User` — mais dont le
fichier vit dans le dossier de l'exécutable, que §1 déclare en lecture seule : « rien n'y est
jamais écrit, déplacé ni supprimé ».

REQ-PROF-065 dit que supprimer un jeu supprime son fichier `.3dn` ; REQ-UI-037 offre l'action
pour tout profil utilisateur. Appliquées telles quelles à un profil du dossier du programme,
elles demandent d'effacer un fichier que AMD-033 §1 interdit de toucher. AMD-033 ne dit rien de
la suppression.

## Choix provisoire

**L'action « Supprimer le jeu » n'est pas offerte pour un profil du dossier du programme** :
`GameLibraryEntry.CanDelete` exige désormais `Source == User` **et**
`Origin == ProfileOrigin.User`. Le dossier de l'exécutable reste intact, et l'entrée ne
réapparaît pas au prochain lancement comme elle le ferait si on retirait l'entrée sans le
fichier.

Référencé dans le code par `// Q-074` (`src/Zax.Profiles/Library/GameLibrary.cs`,
`src/Zax.App/LibraryGameCatalog.cs`) et couvert par
`tests/Zax.Profiles.Tests/ProgramProfilesFolderTests.cs`.

## Autres options écartées

- **Retirer l'entrée de la bibliothèque sans toucher au fichier** : la suppression semblerait
  réussir et le jeu reviendrait au lancement suivant.
- **Masquer le profil par une liste d'exclusions écrite dans le dossier utilisateur** : invente
  un fichier d'état que la spécification ne connaît pas. L'utilisateur peut déjà masquer un
  profil du dossier du programme en plaçant un fichier du même nom chez lui (AMD-033 §2).

# Q-052 — `EngineMode`, `IsProfileMode`, `IsRomMode` : publiés par SPEC-09 §4.1.10, absents de SPEC-05 §4

Ouvert par : R4 (vérificateur indépendant, round 1, partie C), 2026-10-21
Exigences : SPEC-09 REQ-PERS-008 (P1), SPEC-09 §4.1.10 ; SPEC-05 §4.1 et §4.2, REQ-LUA-080

## Contradiction

REQ-PERS-008 (P1) : « Les noms Lua de la colonne « Lua » des tableaux §4.1 et de la table §4.2
font partie du contrat d'interopérabilité : ils **DOIVENT** être exposés exactement (casse
comprise)… »

La ligne `app.engine_mode` de §4.1.10 porte dans sa colonne « Lua » trois noms :

```
`EngineMode`, `IsProfileMode`, `IsRomMode` (membres statiques, lecture ; non utilisés par les
profils embarqués)
```

Aucun des trois n'apparaît dans SPEC-05, qui est pourtant le document normatif du contrat Lua :
ni dans la table des globales §4.1, ni dans la table des membres de `Setting` §4.2, ni dans les
énumérations §4.4. L'inventaire de SPEC-09 §5.6 ne les cite pas non plus, et le critère de
REQ-PERS-008 ne porte que sur les 22 chemins d'accès de ce §5.6.

L'implémentation déclare bien le réglage `app.engine_mode` avec le nom Lua `EngineMode` dans son
catalogue, mais le runtime Lua n'expose aucun des trois membres : `Setting.EngineMode` vaut `nil`.

## Choix provisoire du vérificateur

Lecture littérale de REQ-PERS-008 : les trois noms sont dans la colonne « Lua » de §4.1, donc
exigés. Le critère de l'exigence passe (les 22 chemins fonctionnent) mais son énoncé non.

Verdict retenu : REQ-PERS-008 **PARTIEL** (P1). Test rouge
`PersistenceModelTests.REQ_PERS_008_the_static_engine_mode_members_must_be_exposed`.

## Décision demandée à R0

1. Soit **ajouter** les trois membres à SPEC-05 §4.2 (`Setting.EngineMode` réel lecture seule,
   `IsProfileMode` vrai, `IsRomMode` faux) et les exposer ;
2. soit **marquer** la colonne « Lua » de `app.engine_mode` comme informative (« membres de
   l'éditeur, non exposés sur desktop »), comme le suggèrent la mention « membres statiques » et
   le fait qu'aucun profil embarqué ne les utilise.

La seconde issue est la moins coûteuse et la plus cohérente avec le périmètre (le mode ROM est
celui de l'éditeur, hors périmètre selon SPEC-00 §1).

## Réponse R0 (2026-10-21, normative)
`EngineMode`, `IsProfileMode` et `IsRomMode` sont **requis** (lecture seule) en Lua, avec la sémantique de SPEC-09 §4.1.10 ; ils complètent les tables de SPEC-05 §4.

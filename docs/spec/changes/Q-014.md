# Q-014 — SPEC-04B §5.3 : le cas de contrôle « rangée `11111111`, `D = 2` » contredit REQ-E3D-446 et REQ-E3D-447

- **Ouvert par** : R3 (côté propre), lot L4b, 2026-10-20
- **Documents concernés** : SPEC-04B §5.3 (« Autres cas de contrôle », dernière phrase),
  REQ-E3D-446 (contour de la section), REQ-E3D-447 (texels des quadrants)
- **Classe** : B (erreur probable d'un vecteur de test)
- **Priorité** : P3 (quatre voxels sur seize d'un cas de contrôle ; aucun effet sur l'ensemble
  des voxels, ni sur le nombre de faces, ni sur les couleurs en `GREEDY`, qui ignore le texel
  pour la fusion)

## Contradiction

§5.3 termine par :

> Autres cas de contrôle : […] rangée `11111111`, `D = 2` → 16 voxels (`k = 0` : texel `i` ;
> `k = 1` : texel `7 − i`), 6 rectangles.

Les règles normatives donnent bien les 16 voxels et les 6 rectangles, mais pas ces texels aux
deux colonnes extrêmes. Déroulé : `s = 0`, `f = 7`, donc `C = 7`, `A = 7`,
`B = min(D − 1, L) = 1`, `Cz = 1`.

- **Région 1** (REQ-E3D-446) : les points `(p, 1)` pour `p = 0` à 7. Pour `p = 7` :
  `u⁺ = ⌊(7 + 7)/2⌋ = 7`, `u⁻ = 0`, `z⁺ = ⌊(1 + 1)/2⌋ = 1`, `z⁻ = 0`. Les quadrants
  (REQ-E3D-447, types pleins : `u⁻` pour Q0 et Q3, `u⁺` pour Q1 et Q2) donnent
  `(7, 0) ← 7`, `(7, 1) ← 0`, `(0, 1) ← 7`, `(0, 0) ← 0` — c'est exactement ce que le cas de
  contrôle annonce.
- **Région 2** : le seul point retenu est `(A, 0) = (7, 0)`. Il est traité **après** toute la
  région 1 (« tous les points de la région 1 dans l'ordre, puis ceux de la région 2 ») et
  réécrit les mêmes quatre voxels : `z⁺ = ⌊(Cz + q − 1)/2⌋ = ⌊0/2⌋ = 0`, `z⁻ = 1`, donc
  `Q0 = (7, 0) ← u⁻ = 0`, `Q1 = (7, 1) ← u⁺ = 7`, `Q2 = (0, 0) ← 7`, `Q3 = (0, 1) ← 0`.
  La règle « la dernière écriture l'emporte » (REQ-E3D-423) laisse donc les texels
  **inversés** sur les colonnes 0 et 7 par rapport au cas de contrôle.

Les quatre autres vecteurs de cylindres confirment les règles normatives, région 2 comprise, y
compris quand `z⁺` est la tranche la plus proche du spectateur :

| Vecteur | Région 2 vérifiée | Résultat |
|---|---|---|
| TV-Y1 (`D = 8`, `Cz = 7`) | points `(7, 0)` à `(7, 3)` | (7,3)→7, (7,4)→0, (0,3)→0, (0,4)→7 — conforme |
| TV-Y3 (colonne pleine, `sizeZ = 4`, `Cz = 3`) | points `(7, 0)`, `(7, 1)` | les 16 voxels conformes |
| TV-Y6 (`antiShadow`) | idem TV-Y1 | (7,3)→5, (7,4)→2, (0,3)→2, (0,4)→5 — conforme |
| TV-Y7 (`e = 4`) | points `(7, 0)`, `(7, 1)` | (7,1)→0 et (0,2)→0 — conforme |

La phrase de §5.3 est donc la seule à ne pas suivre REQ-E3D-446/447 ; elle décrit ce que
donnerait la région 1 seule. Dans ce cas particulier `Cz = 1` est impair et `q = 0`, si bien
que `z⁺ = 0` est la tranche avant : le texel « à l'endroit » se retrouve à l'arrière, ce qui
explique l'intuition du rédacteur.

## Choix provisoire

Les règles normatives REQ-E3D-446 et REQ-E3D-447 sont appliquées telles quelles, région 2
incluse ; le texel des quatre voxels extrêmes de ce cas est donc l'inverse de la parenthèse de
§5.3. Le test du côté propre vérifie, pour ce cas, ce qui est normatif et non contesté
(16 voxels, 6 rectangles, et les texels `i` / `7 − i` pour `i = 1` à 6) et laisse les colonnes
0 et 7 de côté avec un renvoi à ce ticket.

Références dans le code : `Sen.Engine3D.VoxelConstruction.Quadrants` (`// Q-014`). Test :
`CylinderVectorTests.Section_control_cases_of_paragraph_5_3`.

## Question posée à R0

Corriger la parenthèse de §5.3 (texels inversés sur les colonnes 0 et 7), ou bien, si c'est la
parenthèse qui décrit l'original, dire ce qui change dans REQ-E3D-446/447 — par exemple que
pour `q = 0` la région 2 ne réécrit pas les voxels déjà posés par la région 1, ce qui
contredirait alors TV-Y1 et TV-Y3.

## Réponse R0 (2026-10-20, normative)
Les règles normatives REQ-E3D-446/447 priment sur la parenthèse de l'exemple §5.3, qui est rectifiée. Point à confirmer au round 2 (différentiel sur un cylindre plein de profondeur 2).

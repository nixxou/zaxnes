**The one real architecture difference.** In .NET `ProfileTile`, `ProfilePattern` and
`PatternVariant` are mutable classes and resolution mutates them in place. In Rust the decoded
model is immutable and shared through `Arc`, and the encoder keys its reference envelopes on
`Arc::as_ptr(..).addr()` (`wire/encoder.rs:374`), so the identity graph is what makes the
rewrite of REQ-PROF-084 lossless. Safe Rust, no interior mutability: resolution **rebuilds** the
patterns it touches, one new `Arc` per distinct old `Arc`, substituted everywhere that `Arc`
appears (both root lists and the memorised slots). The identity graph stays isomorphic, so the
rewrite is unaffected, and the cost falls only on the patterns a resolution actually changed.

The engine cannot borrow the host's profile across frames, so the tile table
(`HashProfileTiles`) owns its own `Arc<ProfilePattern>` list in registration order and the
registry keeps `profile index → PatternId`; `engine.load_profile` takes the table by value.

**The textures are derived, not stored** (decided at step 4). In .NET `RebuildChangedTextures`
recomputes each variant's texture in place every time tiles are resolved, which is the whole of
the V2-34 trap. Here the variant keeps `textureKind` and field 24 exactly as read and **no**
computed texture: `hash::default_texture::PatternTextures::texture_of` derives the texture of a
(pattern, variant) pair where it is used, with the pattern's default texture built on first need.
Three things fall out: the trap cannot happen (there is no cached exclusive-or to go stale, and a
tile resolved in the frame changes the texture by itself), the rewrite of REQ-PROF-084 stays
lossless for free (it writes back field 24 as read), and the `Arc` identity graph the encoder's
reference envelopes key on is never touched. It also settles a question .NET leaves open — a
variant shared between two patterns with different grids would have two different exclusive-ors
and one mutable texture field — which measurement shows is moot in the corpus: **0** variants of
the 101 files are shared between patterns.

## The traps the .NET lot already paid for

- **V2-34** (changelog §2.2): a `textureKind = 2` texture built while the tiles are pending is
  `X XOR 0`. It MUST be rebuilt as soon as the tiles are resolved — at load from the ROM or the
  cache, and again while playing — and the pattern instance must take the **new** texture, not
  only `geo`/`fullWarp`. Without it: wrong colours, black cells, and tiles that stop being full
  (24 vertices instead of 48). This is what the « 3dh = 3dn » test catches.
- **Q-178 §1**: on a mapper-0 CHR-RAM cartridge a visible tile is always also an aligned CHR-RAM
  block, so the two resolution paths are tested separately (engine without a CHR-RAM source for
  the screen path; app with a real core for the CHR-RAM path).
- **Q-178 §3**: `Final_Fantasy_USA` leaves **66** strings pending, not 67 — the four flips of
  REQ-PROF-078 resolve one more than an unflipped scan.
- **Q-179**: the background map is built on every background instance of the frame (hidden ones
  and those whose geometry is not ready included) and on every tile of their shapes; only step 2
  is limited to drawn tiles.
- **Q-180**: `RotOverride` accepts what any `Vector3` write of the API accepts (a bound vector, a
  `Vector2` at z = 0) and raises for anything else; reading gives a `Vector3` copy.

### 2026-11-10 — step 5 done

Where the sixteen bytes of a waiting tile come from, and the cache that spares the search.

- `zax-profiles/src/hash/rom_zones.rs` — `RomZones::of`, REQ-PROF-078 point 1: the sixteen-byte
  header, the 512-byte trainer when bit 2 of byte 6 is set, the NES 2.0 sizes when

- `zax-profiles/src/hash/raw_tile.rs` — `flipped_planes`, the four mirrorings of REQ-PROF-079
  taken from the planes instead of the bytes: vertical is `swap_bytes`, horizontal is
  `reverse_bits().swap_bytes()`, both is `reverse_bits()`. That is what makes the scan cheap,
  since the prefix of REQ-PROF-077 is a function of the planes: a window whose prefix no waiting
  string carries costs four multiplications and no digest at all, and the sixteen bytes are
  rebuilt only for a window the prefix let through. A test confronts it with `flipped` over
  sixteen vectors and the four flips.
- `zax-profiles/src/hash/tiles.rs` — `TileResolver`: which manifest strings have their bytes, the
  prefix filter as a count per prefix (a legacy digest has no prefix and is hashed in full, which
  the 101 files never need), `offer` for one window and its four mirrorings, `resolve_from_rom`
  for the PRG zone then the CHR zone at every byte position with an early stop, and `apply_cache`.
  `apply` rebuilds what a resolution changed: one new `Arc` per distinct old one, substituted in
  both root lists, and the memorised slots — which hold their patterns by value, outside the
  shared graph — rebuilt in place. A resolution that resolves nothing rebuilds nothing, which a
  test checks on the `Arc` addresses themselves.
- `zax-profiles/src/hash/tile_cache.rs` — the cache of REQ-PROF-082: a header line then one
  `<string> <32 hex digits>` per pair. Every entry is verifiable — the string recomputes from the
  bytes, as an identifier or as a legacy digest — and an entry that does not recompute, a file
  without the header, a truncated file and bytes that are not UTF-8 all give nothing. The file is

- `HashProfile` gains `tiles`, `resolve_from_rom`, `apply_tile_cache`, `tile_cache` and

### 2026-11-10 — step 6 done

The canonical 3dh writer, and the one place that decides which writer a profile gets.

**The document carries its format.** `ProfileDocument` gains `hash: Option<HashProfileState>`
(envelope, manifest, `TileResolver`) and `save` branches on it, so "a profile is never converted,
and is rewritten in its own format" (AMD-062 §2, REQ-PROF-084) is one field and one match rather
than a rule every caller has to remember. `hash::profile::read` now returns the document with
that state inside, and `format::load` routes a 3dh through it and then applies the **same** load
rules as a 3dn — the payload is a profile of the schema of SPEC-03 and REQ-PROF-033's "all or
nothing" is the same. The resolution helpers (`resolve_from_rom`, `apply_tile_cache`,
`tile_cache`, `waiting_keys`, `waiting_tile_count`) moved onto `ProfileDocument`, where a 3dn
answers nothing and resolves nothing, which is what lets steps 8 and 9 treat the two formats
alike. The state keeps the envelope **without** its payload: the rewrite encodes a fresh one, so
the bytes read are of no further use and a 2 MB `Final_Fantasy_USA` payload is not carried, nor
cloned, for the life of the document.

- `wire/encoder.rs` — hash mode, the four deviations of REQ-PROF-074 point 3 and REQ-PROF-084:
  the root order (3, 4, 5, 6 first, then 1, 2, 7 to 11), a tile written `3` then `5` (or `4`) and
  never by its planes, field 19 replaced by 24 (only for a `textureKind` of 2) and 25 after field
  23, and field 12 written for **every** pattern of the root lists while a memorised slot's
  pattern keeps the absence read. The texture: a variant read from a 3dh writes its kind and its
  field 24 exactly as read, which is what makes the rewrite lossless by construction — the model
  holds the kind itself, never a computed texture that could go stale (step 4's decision). A
  variant that carries field 19 instead, one this program gave a texture, has its kind read off
  that texture and its field 24 derived with `default_texture::exclusive_or`, the pattern's
  default texture being built only when such a variant exists (no variant of the 101 files is).
- `wire/hash_envelope.rs::encode` — the signature and the version are now the canonical ones
  whatever the file carried: REQ-PROF-084 asks for `Version = "5"`, and `"5"` accepts everything
  `"1"` and `"2"` do (REQ-PROF-072), so writing it loses nothing. All 101 files are already `"5"`.
- `wire/decoder.rs` — a field 5 that is not sixteen bytes is no longer called an identifier: its
  plain hexadecimal form is still what the manifest is asked for (only a declared legacy digest
  can match), but it is recorded as a field-4 string so the writer has a field it can fill. A
  shape no production writer produces; it makes the writer total.

# GAMEHASH: game database keyed by ROM hashes

Branch `gamehash` (worktree `wt-gamehash`), from dev `d02d6dd7`.

Goal: hash each ROM of the catalogue once, find it in databases built into the executable, show
widescreen / hack / RetroAchievements / FCEUX support and pick the 3D profile without loading the
game. Badges from the databases are provisional until checked (hover delay or launch). Unknown
ROMs fall back to the name rules of before.

## Decisions (owner, 2026-11-25)

- One byte range for every key: PRG + CHR at the header's sizes, no header, trainer or overdump
  (`builtin_patches::data_crc`, the No-Intro CRC). Computed once per ROM; other keys derived.
- Each table stays with its feature (`cartdb`, `builtin_patches`, `wide_decode` in `zax-nes`;
  `fceux_validated`, `gamedb` in `zax-app`); all keyed by `data_crc`; no copied facts.
- CSV in the repository is the source; `build.rs` turns it into a sorted Rust table.
- `cartdb.csv` stays Mesen's raw output (`tools/cartdb_from_mesen.py <MesenNesDB.txt>`); the
  lookup tries `data_crc`, trainer + data, then Mesen's own key (J39 in FIDELITY-LEADS).
- `gamedb.csv` (catalogue): `data_crc`, `game` (Hackset metadata file name), `no_intro_name`,
  region, `data_md5`, `file_crc32` list, `ra_md5`, 3D profile. Indexes by game, No-Intro name,
  file CRC.
- `ra_games.csv` from `tools/ra_game_list.py` (needs the owner's RA Web API key).
- `rust/profiles/index.csv`: embedded `.3dn` file -> game.
- User cache `rom_crc.json` v3: hashes + local check results.

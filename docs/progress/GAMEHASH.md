# GAMEHASH: game database keyed by ROM hashes

Branch `gamehash` (worktree `wt-gamehash`), from dev `d02d6dd7`.

Goal: hash each ROM of the catalogue once, find it in databases built into the executable, show
widescreen / hack / RetroAchievements / FCEUX support and pick the 3D profile without loading the
game. Badges from the databases are provisional until checked (hover delay or launch). Unknown
ROMs fall back to the name rules of before.

## Decisions (owner, 2026-11-25)

- One byte range for every key: PRG + CHR at the header's sizes, no header, trainer or overdump
  (`builtin_patches::data_crc`, the No-Intro CRC). Computed once per ROM; other keys derived.
- Each table stays with its feature (`cartdb`, `builtin_patches`, `wide_decode` in `zax-nes`;
  `fceux_validated`, `gamedb` in `zax-app`); all keyed by `data_crc`; no copied facts.
- CSV in the repository is the source; `build.rs` turns it into a sorted Rust table.
- `cartdb.csv` stays Mesen's raw output (`tools/cartdb_from_mesen.py <MesenNesDB.txt>`); the
  lookup tries `data_crc`, trainer + data, then Mesen's own key (J39 in FIDELITY-LEADS).
- `gamedb.csv` (catalogue): `data_crc`, `game` (Hackset metadata file name), `no_intro_name`,
  region, `data_md5`, `file_crc32` list, `ra_md5`, 3D profile. Indexes by game, No-Intro name,
  file CRC.
- `ra_games.csv` from `tools/ra_game_list.py` (needs the owner's RA Web API key).
- `rust/profiles/index.csv`: embedded `.3dn` file -> game.
- User cache `rom_crc.json` v3: hashes + local check results.

## Lot LAUNCH-OUTSIDE (owner, 2026-11-25)

Plan, in this branch:
1. Auto-save per file: leaving a running game (quit, back to the list, another game) writes the
   slot `auto` of its ROM (`<rom>.<ext>`), shown read-only in the Load list (never in Save).

   "Back to library" row that goes to the catalogue. Its per-game options still work (keyed by

   written for a game outside the ROM folder.

   library" row) instead of launching the first one. An archive member is addressed as
   `<archive path>/<entry name>` (the archive read as a folder), so options and saves are per
   game; names and profiles through gamedb (file CRC, data CRC).

## Archives in the ROM folder (owner request, 2026-11-25, branch feat/keys)

- The background lists each `.zip` / `.7z`: its games and the CRC-32 its directory keeps. A game
  the game database knows by that CRC (one image, MD5 known) is not decompressed; the others are
  read in one pass. Listings are kept in `rom_crc.json` (`archives`, stamped by the archive).
- One game: a game's row with a `[ZIP]` / `[7Z]` badge, hashed under the archive's path. Several:
  a folder row under the archive's name, "N jeux" on the right; A opens its games under a
  "< name" row, B or that row goes back to the archive's row. No game: out of the list.
- Profiles and packs of an archive (`rom_file/extras.rs`): a file named as a game goes with it
  only and first; region/timing tags (usa, europe, japan, world, ntsc, pal, whole words) restrict
  a file to the games that have them (regions from the game database, timing from the header);
  generic files last. HD packs in archives: not read (HD packs are not in this branch).
